# Requirements Analysis — AI Engineer Demo Task (GraphOne / FrontierAtlas)

Source of truth: `AI Engineer_August 2026.pdf`. This document decomposes every explicit
requirement into an implementation commitment and flags anything that could cause
disqualification.

## 1. Hard disqualification risk
> "Hallucinated data generated by the LLM will result in immediate disqualification.
> Every record must trace back to a legitimate, valid source URL."

**Implementation commitment:** every canonical record carries `source.url`,
`source.name`, `retrieved_at`, `extraction_method`, `confidence`, and `raw_hash`
(see `src/extraction/schemas.py`). No field is ever synthesized by an LLM without a
verifiable source string it was extracted from. Fields the pipeline cannot verify are
set to `null` / `"UNKNOWN"`, never guessed. GitHub star counts are pulled live from the
GitHub REST API (`src/crawlers/github_enrichment.py`), never estimated.

## 2. Phase I — Massive one-time acquisition
- Concurrent scraper, source-adapter pattern, target: 1,000 startups / 1,000 products /
  1,000 research papers (with GitHub correlation + live stars).
- Architecture must scale to 500k+ records via infrastructure scaling only (no code
  changes) — addressed by bounded async worker pools + queue-based fan-out
  (`src/crawlers/base.py`, `src/pipelines/full_pipeline.py`), horizontally by adding
  worker processes/containers, not by rewriting adapters.

## 3. Phase II — 24-hour freshness (5 news sources + 5 job boards)
- Full-text extraction, robust date normalization (absolute, relative, JSON-LD, OG
  tags, missing metadata), strict 24h freshness gate, dedup via content fingerprint.

## 4. Phase III — Multi-tier LLM extraction
- Fallback chain Gemini Flash → Groq Llama 3 → DeepSeek.
- 413 handling: token estimation + semantic chunking *before* the call, never blind
  end-truncation.
- 429 handling: exponential backoff + jitter + `Retry-After` support + circuit breaker
  + provider fallback.
- All LLM output validated against Pydantic schemas before acceptance.

## 5. Phase IV — Deterministic entity resolution
- Seed list of ~50 known AI orgs, normalization pipeline (unicode → whitespace →
  punctuation → legal-suffix stripping → case → alias dictionary → exact match →
  controlled fuzzy match with confidence score), full raw→canonical mapping log.

## 6. Phase V — Anti-bot / scale strategy
- Priority order: official API → RSS/feed → structured endpoint → plain HTTP →
  Playwright (public JS pages only) → documented "cannot legitimately access"
  fallback. No CAPTCHA/auth bypass — documented as an explicit non-goal.

## 7. Phase VI — Architecture document
- `architecture.pdf`, ≤3 pages, answers: scale strategy, 413/429 handling, distributed
  freshness/dedup, storage justification.

## 8. Deliverables checklist
- [ ] Google Sheet, 6 tabs, min row counts as specified — **requires live network
      access this build environment does not have; see `RUNBOOK.md`.**
- [x] GitHub repo: README, `src/`, `architecture.pdf`
- [ ] Loom video — outside the scope of code; script provided in `docs/loom_script.md`

## 9. Known constraint disclosed to the candidate (me) at build time
This repository was built inside a sandboxed environment whose network egress is
restricted to package registries (pypi/npm/GitHub API) and does not include
arxiv.org, paperswithcode.com, startup directories, news outlets, or job boards.
Every module here is real, tested, runnable code — but the actual 1,000+ row bulk
crawl must be executed on a machine with open internet + your own LLM/GitHub API
keys, per `RUNBOOK.md`. The GitHub star-enrichment step *was* exercised live against
the real GitHub API from this environment as a non-hallucination proof point.
