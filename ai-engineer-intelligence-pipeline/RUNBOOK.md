# Runbook: from this repo to the actual 1,000+ row Google Sheet

## Why this step is separate from the repo build

This repository was assembled inside a sandboxed build environment whose network
egress is restricted to package registries (PyPI, npm, GitHub's REST API). It
cannot reach arxiv.org, paperswithcode.com, startup directories, news RSS feeds, or
job boards. Given the assessment's explicit, non-negotiable rule —

> "Hallucinated data generated by the LLM will result in immediate disqualification.
> Every record must trace back to a legitimate, valid source URL."

— the only responsible options were (a) fabricate rows to hit the count, which is
exactly what's prohibited, or (b) ship the real, tested pipeline code and be
upfront that the bulk crawl needs to run somewhere with open internet. This runbook
is (b).

The one enrichment step reachable from the build sandbox — GitHub star counts via
`api.github.com` — was exercised live (see `scripts/generate_demo_data_report.py`
output), including hitting a real rate limit and watching the circuit breaker open,
which is a better proof of correct 429 handling than a mocked test would be.

## Steps to produce the real submission

1. **Environment**: any machine/container with unrestricted outbound HTTPS.
   ```bash
   git clone <this repo>
   cd ai-engineer-intelligence-pipeline
   pip install -r requirements.txt
   playwright install chromium
   cp .env.example .env   # fill in real keys
   ```

2. **API keys needed** (all free tiers are sufficient for the trial's 1,000-row
   targets):
   - `GEMINI_API_KEY` — Google AI Studio, free tier.
   - `GROQ_API_KEY` — Groq Cloud, free tier.
   - `DEEPSEEK_API_KEY` — DeepSeek platform.
   - `GITHUB_TOKEN` — a personal access token with no special scopes (raises the
     GitHub API limit from 60/hr to 5,000/hr).
   - `PRODUCTHUNT_TOKEN` — optional, for the Product Hunt GraphQL source.

3. **Bring up storage**:
   ```bash
   docker compose up -d postgres redis
   python scripts/seed_entities.py     # loads the 50-org seed list into canonical_entities
   ```

4. **Run the bulk one-time acquisition** (Phase I — startups/products/papers):
   ```bash
   python scripts/run_bulk_ingestion.py --source arxiv --target 1000
   python scripts/run_bulk_ingestion.py --source papers_with_code --target 1000
   python scripts/run_bulk_ingestion.py --source ycombinator_directory --target 1000
   python scripts/run_bulk_ingestion.py --source producthunt --target 1000
   ```
   Each of these uses `AsyncWorkerPool` from `src/crawlers/base.py` — raise
   `--concurrency` (default 10) to scale throughput; the code path is identical at
   500,000 records, only the worker count / number of container replicas changes.

5. **Run the 24-hour freshness crawl** (Phase II — run this last, right before
   generating the Sheet, since freshness is defined relative to "now"):
   ```bash
   python scripts/run_fresh_signals.py --kind news
   python scripts/run_fresh_signals.py --kind jobs
   ```

6. **Validate + export**:
   ```bash
   python scripts/validate_output.py         # checks row counts, schema compliance, dupes
   python scripts/export_google_sheets.py --sheet-id <your_sheet_id>
   ```

7. **Loom video**: record following `docs/loom_script.md`, upload, paste the link
   into the submission form alongside the GitHub repo and Sheet URL.

## What "done" looks like

- `data/exports/final_submission.xlsx` with 6 correctly-headed tabs.
- A public (or shared) Google Sheet mirroring the same 6 tabs.
- Every row traceable via its `source.url` / `source_url` column.
- `data/processed/entity_mapping_log.csv` showing raw→canonical resolutions with
  method + confidence for every entity encountered.
